# ChatToImage V1 定价策略

> 状态：已确认，待实现  
> 最后更新：2026-09-09  
> 适用市场：海外自助式 AI 图片生成用户  
> 结算货币：美元（USD）

本文档是 ChatToImage V1 的定价与积分规则基准。它记录已经确认的产品方案，不代表当前代码已经按此配置。实施时应以本文档为目标，同时核对支付、积分、生成扣费和页面文案。

## 1. 定价总览

### 1.1 免费试用

| 项目     | 规则                                 |
| -------- | ------------------------------------ |
| 注册赠送 | 8 积分                               |
| 有效期   | 注册后 7 天                          |
| 模型权限 | 可以选择所有已上线模型，不做人为限制 |
| 扣费方式 | 按所选模型和分辨率正常扣除积分       |
| 失败处理 | 生成失败退还本次积分                 |
| 支付要求 | 无需绑定支付方式                     |

“可使用所有模型”指不设置免费用户专属的模型权限墙。8 积分仍是统一余额，因此单次费用超过 8 积分的配置需要先购买积分或订阅。例如，14 积分的 Nano Banana Pro 4K 不在首次赠送余额的可支付范围内。

按当前上游基础成本计算，单个完成注册的免费用户最多消耗约 `8 × ¥0.036 = ¥0.288`，获客成本可控。

## 4. 积分规则

1. 生成前必须显示预计消耗的积分。
2. 余额不足时不提交任务，并引导用户订阅或购买积分包。
3. 生成任务失败时退还本次已扣积分。
4. 同一账户存在多批积分时，优先消耗最早到期的积分。
5. 月付积分按月发放；年付积分一次发放并在 365 天后到期；积分包在购买后 365 天到期。
6. 订阅结束不会删除尚未到期的积分；积分仍按其原有效期处理。
7. 供应商调价或模型成本变化时，可以调整未来生成任务的积分消耗，但不追溯已经完成的任务。

## 5. 单位经济测算

### 5.1 测算假设

- 上游基础价格：¥36 / 1,000 积分，即 ¥0.036 / 积分。
- 汇率假设：$1 ≈ ¥7.10。
- 支付通道费率：按销售额的 4% 估算。
- 暂不计入存储、下载流量、退款、税费和人工支持成本。
- 未使用积分会改善实际利润，但定价安全性应先按积分全部使用的保守场景判断。

## 6. 为什么不完全照搬 Pixmira

[Pixmira 的价格页](https://pixmira.ai/pricing)可以作为价格锚点，但不能直接证明它的成本结构适合 ChatToImage。其部分图片模型将 1K、2K、4K 设置为相同积分，可能依赖供应商协议、批量折扣、未使用积分、模型补贴或整体产品组合来覆盖成本。

ChatToImage V1 保留相近的美元价格带，但给予更多订阅积分，并继续按模型和分辨率差异扣费。这样既能保持市场竞争力，也能让高成本请求由对应积分覆盖。

调研时记录的 Pixmira 月付价格为：$9.90 / 200 积分、$19.90 / 500 积分、$49.90 / 2,000 积分、$99.90 / 4,000 积分。竞争对手价格可能随时变化，不能作为本站自动同步的数据源。

## 7. 上线后的验证指标

上线后每周查看一次，积累至少 30 天数据后再决定是否调整价格：

- 免费用户完成首次生成的比例。
- 免费用户转付费的比例。
- Starter、Creator、Pro 的购买占比。
- 各方案积分的实际使用率。
- 各模型和分辨率的使用占比。
- 每个方案扣除支付费和上游成本后的贡献毛利率。
- 月付订阅流失率。
- 订阅用户额外购买积分包的比例。

V1 的工作目标是整体直接成本口径的贡献毛利率不低于 65%，并观察 Creator 是否能成为主力方案。未获得真实数据前，不继续增加套餐数量。

## 8. 实施清单

本文档确认后，实施应至少覆盖以下位置：

- 将 `src/config/pricing.ts` 的模板商品替换为本文档中的月付、年付和积分包。
- 将 `src/modules/ai/service.ts` 的统一 5 积分扣费改为按模型和分辨率计费。
- 将注册赠送从当前页面文案中的 20 积分调整为 8 积分、7 天有效。
- 更新中英文价格页、首页价格摘要、FAQ 和生成按钮旁的积分提示。
- 确认支付成功、订阅续费、积分到期和失败退款行为与本文档一致。
- 在管理后台配置注册赠送积分，并完成各支付渠道的商品映射。
